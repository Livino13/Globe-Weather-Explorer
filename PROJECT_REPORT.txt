**Introduction**
Global Weather Explorer is a client-side web application intended for exploring and visualizing weather information across locations. It uses a modern frontend toolchain (Vite + TypeScript) and standard web technologies (HTML/CSS/JS). The project focuses on a concise, responsive UI for fetching and displaying weather data while keeping the codebase minimal and maintainable.

**System Design**
- **Architecture:** Single Page Application (SPA) or small multi-page app built with Vite. The app is frontend-only and interacts with external weather APIs to retrieve data.
- **Components:** UI divided into small components: search/location input, current conditions panel, forecast visualization, and settings/cache controls.
- **Data flow:** User input -> API request -> response parsing -> UI update. A thin client-side cache can be used to reduce repeated API calls.
- **Build & Tooling:** Uses Vite for fast development server, TypeScript for type safety, and npm scripts for common tasks (`start`, `build`, `preview`).

**Implementation (only important parts)**
- **Entry point:** `index.html` mounts the app. The app bootstraps from a TypeScript entry file (typical pattern: `src/main.ts`) compiled and served by Vite.
- **API integration:** Centralized API module handles requests to a weather data provider. Key responsibilities:
  - Build request URLs with required parameters and API key (keep keys out of source control).
  - Provide a typed response model and helper functions to normalize provider responses.
  - Retry/backoff or graceful error handling for network issues.
- **Data caching:** Small in-memory cache (and optional `localStorage`) keyed by location + units to limit redundant API calls and improve perceived performance.
- **Error handling & UX:** Show inline status indicators: loading spinner, user-friendly error messages, and retry affordances.
- **Type safety:** Strong TypeScript interfaces for API responses, component props, and utility functions to avoid runtime errors.
- **Build config:** `vite.config.ts` provides aliases, environment handling, and any needed plugin configuration (e.g., for static asset handling or environment variables).
